游戏文本日英中翻译说明

请根据日文和英文，将指定范围内的游戏文本翻译或校订为自然、准确、完整的简体中文。

一、工作分工
- 主 agent 使用 gpt-6.1-sol，负责确认文件与范围、建立完整术语表、提取上下文、分批分发、维护进度、语义审校、格式校验和最终合并。发现文字问题交回翻译 agent 修正。
- 多个翻译 agent 使用 gpt-6-luna，只负责分配范围内的文字翻译，不修改主文件、工具或术语库，不运行测试、不继续委派。
- 各批次不重叠，提供日英原文、官中参考、相关术语、必要上下文和格式要求。任务清单、译文及进度保存到工作目录，续接时读取文件，不依赖聊天记忆；不记录逐条保留或修改理由。

二、翻译要求
1. 按用户指定的文件和任务类型工作。重译、校订、补全或单条修改分别执行，不擅自换版本或扩大范围。
2. 结合日英和上下文理解原意，准确保留指代、语气、否定、数量、条件及因果。上下文用于消歧，不把前后句的信息重复补进本句，不添加原文没有的设定或解释。
3. 专有名称优先采用用户确认译法及可靠官方中文，全文保持一致。术语表应覆盖人物、地名、组织、装备、设施和固定项目；标签没有中文时也要查同名正文。普通句子依原文自行翻译，不照抄整句官中，不编造缺乏依据的译名。
4. 缩写按实际动作和对象判断，区分导弹、发射装置、系统、阵地等含义，不能机械全局替换。真实型号、编号、呼号、评级和方向字母按用途保留，剧情用语与界面标签分别处理。
5. 对白自然，通信简练，菜单和名称简洁；长文完整处理。使用规范简体中文和中文标点，不给专名添加无意义的引号或句号，也不机械删除有意义的符号。

三、文件与格式
- 只修改授权译文字段，保持原结构、列数、源文、ID、顺序、格式参照及字符串／数组形状，不增删条目，不为省 token 压缩列数。
- 保留变量、标签及属性、图标、控制字符、首尾空白和指定格式的换行数量与类型；正确处理 JSON 转义，不改格式参照绕过错误。
- 使用 UTF-8，中文保持可读明文，文件缩进和逐条排版与原来一致。特殊值按实际工具定义处理，不用空字符串、null 或占位文字冒充完成或保留旧译文。

四、审校与交付
- 主 agent 核对实际覆盖范围、语义、术语一致性、错译漏译和残留英文。正则只用于提取候选，不能把所有英文都判为漏译，也不能因含有专名就放过整句。
- 对最终文件进行必要文本校验，核对结构、换行、标签、变量及字体支持；有实际导入器时使用其校验功能。禁止图像识别测试和重复无意义测试，不擅自修改游戏、工具或执行部署。
- 字段已填、批次已提交或格式通过，都不等于翻译完整正确。未完成项如实报告；最终 JSON 不添加注释、解释或修改理由，单独简报写明准确路径、实际处理范围及校验结果。
